ITWorx · 2026

Frontend API and error-handling audit

FrontendAI
BFFAuth0 / OIDCResilience

I audited every API call, backend-for-frontend route and sign-in flow in the product's frontend to find where users could end up stuck, misled, or looking at stale data. I used an AI agent to sweep the codebase, then checked and prioritised what it found myself. The result was 15 findings, each with a severity, a concrete failure scenario, a fix pattern and an effort estimate.

3 critical 4 high 5 medium 3 low
CriticalRequests with no timeout

A slow CMS or identity provider could freeze pages for every user. Fix: one shared fetch-with-timeout utility for all server routes.

HighSilent session expiry

When token refresh failed, the UI looked normal until the next click failed. Fix: a session-expired banner with a clear "Sign in again" action.

HighForms failing quietly

Users got no feedback on a failed submit and could send it twice. Fix: inline errors and a disabled button while submitting.

MediumOne error breaks the whole page

A single widget crash took down unrelated content. Fix: an error boundary around each widget region.
